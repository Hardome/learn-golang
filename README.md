# Урок 021. Карты в Go

**Карта** (`map`) хранит неупорядоченные пары «ключ — значение». Тип `map[K]V` задаёт тип ключа `K` и тип
значения `V`. Ключи сопоставляются по правилам `==`, поэтому присваивание по равному ключу заменяет значение
существующей записи. Значение карты ссылается на общие данные, а стандартный рантайм хранит их в хеш-таблице.

Запускаемые примеры собраны в [hello.go](hello.go). Команда `go run hello.go` требует Go 1.23 или новее
из-за итераторов пакета `maps`.

## Объявление и инициализация

### Нулевая, пустая и заполненная карта

```go
var people map[string]int          // Нулевое значение карты равно nil.
empty := map[string]int{}          // Пустая карта готова к записи.
scores := map[string]int{
    "Tom": 1,
    "tom": 2,                     // Строки сравниваются побайтово, регистр различается.
}

fmt.Println(people, empty)         // map[] map[]
fmt.Println(people == nil, empty == nil) // true false
fmt.Println(scores)                // map[Tom:1 tom:2]
```

В многострочном литерале после последней пары нужна запятая, если закрывающая скобка вынесена на следующую строку.
Повторяющиеся константные ключи дают ошибку компиляции. Если равенство ключей выясняется при вычислении выражений,
лучше записать пары отдельными присваиваниями, чтобы явно задать, какое значение победит.

### Создание через `make`

```go
scores := make(map[string]int)      // Пустая карта без оценки размера.
planned := make(map[string]int, 64) // Ожидается примерно 64 записи.
fmt.Println(len(scores), len(planned)) // 0 0
```

Второй аргумент `make` подсказывает реализации начальный размер. Карта может вырасти за пределы оценки. Точный
объём выделенной памяти зависит от реализации. `len` сообщает количество записей, а `cap` для карт не определён.
`new(map[string]int)` возвращает указатель на нулевую карту, которую перед записью всё равно нужно инициализировать.

## Чтение, запись и удаление

### Нулевое значение и форма `comma-ok`

Чтение `m[key]` возвращает нулевое значение типа `V`, если ключ отсутствует или карта равна `nil`. Например,
для `int` это `0`, для `string` это `""`, для указателя, среза или вложенной карты это `nil`.
Форма `value, ok := m[key]` отличает отсутствующий ключ от записи с нулевым значением.

```go
scores := map[string]int{"Tom": 0}
score, present := scores["Tom"]
fmt.Println(score, present)           // 0 true
score, present = scores["Alice"]
fmt.Println(score, present)           // 0 false

if score, ok := scores["Tom"]; ok {
    fmt.Println(score)               // 0
}
```

### Добавление, обновление и очистка

```go
scores := map[string]int{"Tom": 1}
scores["Bob"] = 2                        // Добавляет новый ключ.
scores["Tom"]++                          // Увеличивает значение существующего ключа.
scores["Alice"]++                        // Начинает с 0 и сохраняет 1.
delete(scores, "Bob")                    // Удаляет запись.
delete(scores, "Kate")                   // Отсутствующий ключ ничего не меняет.
fmt.Println(scores)                      // map[Alice:1 Tom:2]
clear(scores)                            // Go 1.21+. Удаляет все записи.
fmt.Println(len(scores), scores == nil)  // 0 false
```

```go
var scores map[string]int
score, ok := scores["Tom"]
delete(scores, "Tom")                   // Допустимо для nil-карты.
clear(scores)                           // Допустимо для nil-карты.
fmt.Println(score, ok, len(scores))     // 0 false 0
// scores["Tom"] = 1                    // Паника при записи в nil-карту.
```

Операции с ключом предполагают, что ключ допустим. Интерфейсный ключ с несравнимым динамическим значением
может вызвать панику даже при чтении из пустой карты или удалении из неё.

## Какие ключи допустимы

### Сравнимые типы

Ключом могут быть числа, строки, `bool`, указатели, каналы, интерфейсы, массивы со сравнимыми элементами и
структуры со сравнимыми полями. Срезы, карты и функции ключами быть не могут. Тип значения `V` такого
ограничения не имеет. Типизированный ключ должен быть присваиваем типу `K`. Если типы различаются и
не допускают неявного присваивания, требуется явное преобразование.

```go
type Route struct {
    Method string
    Path   string
}
hits := map[Route]int{{Method: "GET", Path: "/"}: 1}
fmt.Println(hits[Route{Method: "GET", Path: "/"}]) // 1
fmt.Println(hits[Route{Method: "POST", Path: "/"}]) // 0
// _ = map[[]byte]int{} // Ошибка компиляции: ключ-срез несравним.
```

Указатели сравниваются по правилам равенства указателей. Два указателя на разные объекты с равными полями
обычно дают разные ключи. Для указателей на разные переменные нулевого размера спецификация допускает как
равенство, так и неравенство. Если нужна идентичность по данным, удобно использовать сравнимую структуру.

### Интерфейсные ключи

`map[any]V` принимает значения разных динамических типов. Равенство интерфейсных ключей требует одинакового
динамического типа и равных значений. Приведение к `any` не делает срез сравнимым. То же ограничение
действует для структур и массивов с интерфейсными полями или элементами.

```go
labels := map[any]string{int(1): "int", int64(1): "int64", nil: "nil"}
fmt.Println(labels[int(1)], labels[int64(1)], labels[nil]) // int int64 nil
// labels[[]int{1}] = "slice" // Паника: динамический тип []int несравним.
```

Для обобщённой карты параметр ключа объявляют как `K comparable`. Начиная с Go 1.20 интерфейсный тип
вроде `any` удовлетворяет этому ограничению, но проверка сравнимости конкретного значения при операции
с ключом сохраняется.

### Особый случай `NaN`

`NaN != NaN`, поэтому каждый такой ключ при записи создаёт отдельную запись. `range` видит эту запись,
но прочитать или удалить её по ключу нельзя даже с тем же значением `nan`. `clear` удаляет и такие записи.

```go
nan := math.NaN()
values := map[float64]string{nan: "первый"}
values[nan] = "второй"                   // Ключ не совпадает с существующим.
_, ok := values[nan]
delete(values, nan)                      // Поиск совпадения ничего не находит.
fmt.Println(len(values), ok)             // 2 false
clear(values)
fmt.Println(len(values))                 // 0
```

## Перебор

### Порядок `range` и вывод через `fmt`

`for key, value := range m` получает пары. `for key := range m` получает только ключи. Для `nil`-карты
цикл выполняет ноль итераций. Порядок `range` не задан и может меняться между обходами одной карты.
Стандартное форматирование `fmt` сортирует ключи при печати карты. Для строк это лексикографический
порядок, который даёт `map[Sam:4 TOM:3 Tom:1 tom:2]`.

Для воспроизводимой обработки строковых ключей отсортируйте их перед обходом. `maps.Keys` возвращает
итератор ключей, а `slices.Sorted` собирает и сортирует их. Обе функции появились в Go 1.23.

```go
scores := map[string]int{"Tom": 1, "Bob": 2}
for _, name := range slices.Sorted(maps.Keys(scores)) {
    fmt.Println(name, scores[name]) // Сначала Bob 2, затем Tom 1.
}
```

Этот способ повторно ищет значение по ключу. Если возможны ключи вроде `NaN`, собирайте пары за один
проход, а порядок определяйте сравнением самих собранных пар.

### Изменение карты во время обхода

В одной горутине запись и удаление во время `range` разрешены. Если удалить запись до того, как цикл
до неё дошёл, цикл её пропустит. Новая запись может попасть в текущий обход или быть пропущена.
Присваивание переменной `value` меняет только переменную цикла. Для изменения записи используйте ключ.

```go
scores := map[string]int{"Tom": 1, "Bob": 2}
for name, score := range scores {
    if score < 2 {
        delete(scores, name)       // Удаляет текущую запись Tom.
    }
}
fmt.Println(scores)                 // map[Bob:2]
```

При семантике Go 1.22 и новее `:=` в заголовке `range` создаёт отдельные переменные каждой итерации.
При `=` значения записываются в заранее объявленные переменные, общие для всех итераций.

## Копирование и изменение значений

### Присваивание и передача в функцию

Присваивание карты и передача её в функцию копируют значение карты. Обе переменные после копирования
ссылаются на общее содержимое. Запись по ключу, `delete` и `clear` видны через обе переменные.
Присваивание новой карты меняет только ту переменную, которой её присвоили.

```go
scores := map[string]int{"Tom": 1}
shared := scores
shared["Tom"] = 2
fmt.Println(scores["Tom"]) // 2
shared = map[string]int{"Tom": 9}
fmt.Println(scores["Tom"], shared["Tom"]) // 2 9
```

`maps.Clone` из Go 1.21 создаёт независимую карту и сохраняет `nil` при клонировании `nil`-карты.
Копия поверхностная. Вложенные карты, указатели и базовые массивы срезов могут оставаться общими.
Глубокое копирование этих данных нужно выполнять отдельно по правилам предметной области.

```go
groups := map[string][]string{"dev": {"Tom"}}
cloned := maps.Clone(groups)
cloned["dev"][0] = "Bob"              // Срезы используют один базовый массив.
cloned["qa"] = []string{"Alice"}      // Новый ключ есть только в копии.
fmt.Println(groups["dev"], len(groups), len(cloned)) // [Bob] 1 2
```

### У элемента карты нельзя взять адрес

`m[key]` можно использовать слева от присваивания, но выражение неадресуемо. Поэтому `&m[key]` и
изменение поля структуры через `m[key].Field = x` запрещены. Скопируйте структуру, измените поле
и запишите её обратно. Если в карте лежит указатель на структуру, можно изменить объект через него,
предварительно проверив указатель на `nil`.

```go
type Player struct{ Score int }
players := map[string]Player{"Tom": {Score: 1}}
// players["Tom"].Score++ // Ошибка компиляции: элемент карты неадресуем.
player := players["Tom"]
player.Score++
players["Tom"] = player
fmt.Println(players["Tom"].Score) // 2
```

У среза, хранящегося в карте, можно изменить элемент базового массива. Если `append` вернул новый
заголовок среза, его нужно записать обратно в карту, иначе длина записи останется прежней.

## Сравнение карт

Операторы `==` и `!=` для карты разрешены только при сравнении с `nil`. Сравнение через два
интерфейса с одинаковым динамическим типом карты может скомпилироваться, но вызовет панику.

### `maps.Equal` и `maps.EqualFunc`

`maps.Equal` проверяет совпадение ключей и сравнивает значения через `==`. Для пустой карты и
`nil`-карты результат `true`. Если значения требуют другого правила равенства, `maps.EqualFunc`
принимает функцию сравнения. Обе функции появились в Go 1.21.

```go
scores := map[string]int{"Tom": 1}
fmt.Println(maps.Equal(scores, map[string]int{"Tom": 1})) // true
fmt.Println(maps.Equal(scores, map[string]int{"Tom": 2})) // false
fmt.Println(maps.Equal(map[string]int(nil), map[string]int{})) // true

a := map[string][]int{"Tom": {1, 2}}
b := map[string][]int{"Tom": {1, 2}}
fmt.Println(maps.EqualFunc(a, b, slices.Equal[[]int, int])) // true
```

При `V = any` вызов `maps.Equal` может паниковать на сравнении значений одного несравнимого
динамического типа. `maps.Equal` и `maps.EqualFunc` ищут ключи по правилам карты, поэтому ключ
`NaN` мешает признать карту равной даже самой себе.

### `reflect.DeepEqual`

`reflect.DeepEqual` требует одинаковых типов карт и различает `nil` и выделенную пустую карту.
Карты с общей таблицей считаются глубоко равными сразу. Для разных таблиц ключи сопоставляются
обычным равенством Go, а значения сравниваются рекурсивно по правилам `reflect.DeepEqual`.

```go
a := map[string][]int{"Tom": {1, 2}}
b := map[string][]int{"Tom": {1, 2}}
fmt.Println(reflect.DeepEqual(a, b)) // true
fmt.Println(reflect.DeepEqual(map[string]int(nil), map[string]int{})) // false
```

Например, указатели-ключи сопоставляются как указатели. Для разных карт ключи `NaN` не сопоставятся,
а общая таблица пройдёт проверку идентичности.

## Множество и группировка

Для множества подходит `map[T]struct{}`. Пустая структура не хранит данных о значении, а наличие ключа
показывает `ok`. Для группировки подходит `map[K][]V`. У отсутствующего ключа возвращается `nil`-срез,
и его можно передать в `append`.

```go
seen := map[string]struct{}{"Tom": {}}
_, present := seen["Tom"]
fmt.Println(present) // true

groups := make(map[string][]string)
groups["dev"] = append(groups["dev"], "Tom") // Ключа ещё нет, append начинает с nil-среза.
fmt.Println(groups["dev"])                  // [Tom]
```

Во вложенной карте перед записью по двум ключам создайте внутреннюю карту, если её ещё нет. Запись в `nil`-карту
вызовет панику.

## Доступ из нескольких горутин

После передачи карты другим горутинам с синхронизацией её можно читать одновременно, пока никто её не меняет.
Если есть писатель, защищайте и чтение, и запись, включая `len` и `range`. Для обычной карты подойдёт `sync.Mutex`.

Стандартный рантайм использует хеш-таблицу. Спецификация не задаёт сложность операций или схему роста таблицы.
