# Урок 017. Определения типов и псевдонимы в Go

У `type` две формы. `type mile uint` определяет отдельный тип, а `type mileAlias = uint` даёт ещё одно имя
существующему типу `uint`. Идентичность типа определяет, где Go принимает значение без преобразования
и какие методы ему доступны.

| Объявление | Результат |
| --- | --- |
| `type mile uint` | Новый определённый тип `mile` с базовым типом `uint`. |
| `type mileAlias = uint` | Псевдоним. Имена `mileAlias` и `uint` обозначают один тип. |
| `type routeMile = mile` | Псевдоним для уже определённого типа `mile`. |

**Базовый тип** (underlying type) задаёт общие свойства значения. Например, `mile` имеет диапазон
и арифметические операции `uint`, сохраняя собственную идентичность. Переменные с типами `mileAlias`
и `uint` можно присваивать друг другу, потому что это два имени одного типа.

Запустите [hello.go](hello.go) командой `go run hello.go`. Для примера с обобщённым псевдонимом нужен Go 1.24
или новее.

## Определённые типы для единиц измерения

Функция принимает мили. Отдельный тип для километров помогает компилятору обнаружить ошибку при вызове.

```go
type mile uint
type kilometer uint
type routeMile = mile

func distanceToEnemy(distance mile) {
    fmt.Println(distance, "миль до противника")
}

// Внутри функции:
var distance mile = 5
fmt.Println(distance) // 5
distance += 5
fmt.Println(distance) // 10
distanceToEnemy(distance) // 10 миль до противника

var routeDistance routeMile = distance
distanceToEnemy(routeDistance) // 10 миль до противника

km := kilometer(16)
raw := uint(10)
// distanceToEnemy(km)  // Ошибка компиляции: kilometer и mile — разные типы.
// distanceToEnemy(raw) // Ошибка компиляции: uint и mile — разные типы.
distanceToEnemy(mile(raw)) // 10 миль до противника, если raw уже измерен в милях.
fmt.Println(mile(km))      // 16, преобразование типа оставило число прежним.
```

`mile(km)` преобразует `kilometer(16)` в `mile(16)`. Число остаётся тем же, поскольку у типов одинаковый
базовый тип. Для перевода единиц нужен отдельный расчёт, например `float64(km) / 1.609344`.

Число `5` в `var distance mile = 5` или `distanceToEnemy(5)` является нетипизированной константой.
Её можно использовать, потому что она представима в типе `mile`. Значения `-1` и `1.5` в таком контексте
не компилируются. После `count := 5` переменная `count` имеет тип `int`, поэтому вызов
`distanceToEnemy(count)` требует преобразования.

Если объявить `type mileAlias = uint` и `type kilometerAlias = uint`, обе переменные можно передать
параметру типа `uint` без преобразования. Такие имена помогают читателю, но компилятор видит один тип.
Псевдоним `routeMile`, напротив, сохраняет идентичность `mile` и вместе с ней проверку единиц.

## Присваивание, преобразование и составные типы

Для обычных типов важны два правила присваивания. Значение можно присвоить переменной идентичного типа.
Значение также можно присвоить переменной с идентичным базовым типом, если хотя бы один из двух типов
неименованный. Эти правила применяются и к аргументам функций. У каналов, интерфейсов, `nil`,
констант и параметров типов есть дополнительные правила.

`mile` и `uint` оба именованные. Для них явное преобразование `mile(raw)` допустимо, хотя прямое
присваивание недопустимо. У срезов проверяется тип элемента. `[]mile` и `[]uint` отличаются даже по
базовому типу, поэтому `[]mile(rawDistances)` для `rawDistances` типа `[]uint` не компилируется.
Можно создать новый срез и преобразовать элементы по одному. Срезы `[]routeMile` и `[]mile` идентичны.

## Короткое имя для сигнатуры функции

`func(int, int) int` описывает функцию с двумя аргументами типа `int` и результатом типа `int`.
Псевдоним `BinaryOp` сокращает запись и подсказывает назначение параметра.

```go
type BinaryOp = func(int, int) int

func action(left, right int, op BinaryOp) {
    fmt.Println(op(left, right))
}

func add(left, right int) int {
    return left + right
}

// Внутри функции:
var rawOperation func(int, int) int = add
action(10, 25, rawOperation) // 35

var operation BinaryOp = rawOperation
action(10, 35, operation) // 45
```

Сравните два присваивания при одинаковом базовом типе.

```go
type NamedBinaryOp func(int, int) int
type anotherOperation func(int, int) int

var namedOperation NamedBinaryOp = rawOperation // Тип rawOperation неименованный.
// var invalid anotherOperation = namedOperation // Ошибка компиляции. Оба типа именованные.
other := anotherOperation(namedOperation)
action(2, 3, other) // 5
```

Из `rawOperation` значение можно присвоить напрямую. Для перехода между `NamedBinaryOp` и `anotherOperation`
нужно преобразование. У параметра `op` функции `action` неименованный тип `BinaryOp`, поэтому туда
можно передать `other`. Идентичность частей сигнатуры также важна. Функции `func(mile)` и `func(uint)` имеют
разные типы, а `func(routeMile)` и `func(mile)` обозначают один тип. Нулевое значение любого из
этих функциональных типов равно `nil`. Вызов функции через `nil` приводит к панике.

## Методы и идентичность во время выполнения

Определённый тип может иметь свои методы. Получатель должен быть определённым в том же пакете типом
или указателем на него. Сам тип, к которому привязывается метод, не может быть указателем или интерфейсом.
Псевдоним сохраняет набор методов типа, который он обозначает.

```go
type mile uint
type routeMile = mile
type raceMile mile

func (distance mile) Double() mile { return distance * 2 }

// Внутри функции:
var distance routeMile = 5
fmt.Println(distance.Double()) // 10
// fmt.Println(raceMile(distance).Double()) // Ошибка: у raceMile нет метода Double.
```

Новое определение `type raceMile mile` не получает методы, объявленные на `mile`. Для
интерфейсного типа новое определение сохраняет методы, заданные самим интерфейсом. Методы
элементов составного типа также сохраняются, включая методы, продвигаемые из встроенных полей.

Метод можно объявить с получателем, записанным через обычный псевдоним локального определённого
типа. Метод будет принадлежать исходному типу. Через `type mileAlias = uint` нельзя добавить метод
к `uint`, как и через псевдоним нельзя добавить метод к типу другого пакета или к неименованному
типу функции. Обобщённый псевдоним и псевдоним инстанцированного обобщённого типа нельзя использовать
как получатель, включая косвенные ссылки через другие псевдонимы и указатели.

Интерфейс хранит динамический тип значения. После `value := any(routeMile(5))` утверждение
`value.(mile)` успешно, а `value.(uint)` в форме с `ok` возвращает `false`. В переключателе
типов `case mile` и `case routeMile` будут дубликатами.

## Где нужны псевдонимы

- При переносе публичного типа в другой пакет старый пакет может оставить
  `type Config = newpkg.Config`. Оба пути импорта продолжают обозначать один тип, поэтому
  пользователи могут переходить на новый пакет постепенно. Такой импорт не должен образовать цикл.
- Для длинной сигнатуры псевдоним вроде `BinaryOp` делает назначение параметра заметнее и сохраняет
  идентичность типа. Для единиц измерения и собственных методов подходит определение типа.
- Предобъявленные псевдонимы `byte` и `rune` обозначают `uint8` и `int32`. Предобъявленное имя
  `any` обозначает `interface{}`. Например, `[]byte` и `[]uint8` идентичны.

## Версии Go и обобщённые псевдонимы

Объявления псевдонимов появились в Go 1.9, `any` в Go 1.18, а обобщённые псевдонимы полностью
поддерживаются с Go 1.24. Обобщённый псевдоним нужно инстанцировать аргументами типов при использовании.

```go
type set[K comparable] = map[K]bool

// Внутри функции:
var active set[string] = map[string]bool{"go": true}
fmt.Println(active["go"], active["rust"]) // true false
```

Ограничение `comparable` нужно для ключей карты. `set[string]` и `map[string]bool` обозначают
один тип. Объявление `type Identity[T any] = T` недопустимо, поскольку `T` объявлен в самом
псевдониме. Внутри обобщённой функции допустимо объявить `type Local = T`, если `T` является
параметром окружающей функции. Псевдоним может зафиксировать часть аргументов другого обобщённого
типа. Например, при наличии `type Map[K comparable, V any] map[K]V` можно объявить
`type MapSet[K comparable] = Map[K, bool]`.
