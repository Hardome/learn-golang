# Урок 022. Пакеты и их импорт

**Пакет** — единица организации кода в Go. Его файлы разделяют объявления уровня пакета, а другие пакеты получают
доступ к экспортируемым именам через импорт. Команда `go` обычно собирает пакет из подходящих файлов одного каталога.

Запускаемые примеры собраны в [hello.go](hello.go). Из корня репозитория выполните `go run hello.go`.

## Объявление пакета и точка входа

Каждый Go-файл начинается с объявления `package` после возможных комментариев. За ним идут импорты, затем объявления
констант, типов, переменных и функций. Имя пакета — идентификатор. Использовать `_` в объявлении пакета нельзя.

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello, Go!") // Hello, Go!
}
```

Для исполняемой программы нужен пакет `main` с функцией `func main()` без параметров и результатов. Она вызывается
после инициализации всей программы. Когда `main` возвращается, программа завершается, даже если другие горутины
ещё работают. Команда `go` запрещает импорт пакета `main`.

## Несколько файлов одного пакета

При обычной сборке каталога все выбранные файлы пакета имеют одинаковое объявление `package`. Подкаталог со своими
файлами образует отдельный пакет, даже если в нём указано такое же имя. Суффиксы вроде `_windows.go` и директивы
`//go:build` влияют на выбор файлов при сборке. Файлы `*_test.go` подключает `go test`. Имя вроде
`greeting_test` в каталоге пакета `greeting` образует отдельный пакет для внешних тестов.

В примере ниже оба файла находятся в одном каталоге. В `hello.go` объявлена функция `sayHello`.

```go
package main

import "fmt"

func sayHello() {
    fmt.Println("Hello, Go!") // Hello, Go!
}
```

В `main.go` функция доступна напрямую, поскольку объявлена в том же пакете.

```go
package main

func main() {
    sayHello() // Hello, Go!
    // fmt.Println("Hello, Go!") // Ошибка: fmt импортирован только в hello.go.
}
```

Объявления уровня пакета видны во всех его файлах, включая имена со строчной буквы. Импорт вводит имя только в файл,
где он записан. Если в двух файлах используются функции `fmt`, каждый файл импортирует `"fmt"` самостоятельно.

```text
go run main.go hello.go
go build -o app.exe main.go hello.go
```

Первая команда выводит `Hello, Go!`, вторая создаёт `app.exe`. На Linux и macOS можно указать `-o app`.
При передаче списка файлов `go` собирает пакет из перечисленных файлов одного каталога и игнорирует ограничения
сборки этих файлов. Команда `go run main.go` в примере завершится ошибкой `undefined: sayHello`.
При сборке по каталогу команда `go` сама выбирает файлы. В каталоге пакета `main` внутри модуля подойдут
`go run .` и `go build .`.

## Объявления импорта

### Путь импорта и имя пакета

В объявлении `import` строковый литерал задаёт **путь импорта**. В коде перед точкой по умолчанию используется
**имя пакета** из объявления `package`. Обычно оно совпадает с последним компонентом пути. Например, для
`"encoding/base64"` имя пакета — `base64`, а для `"math/rand/v2"` — `rand` (пакет появился в Go 1.22).
Идиоматичное имя пакета короткое, в нижнем регистре и без подчёркиваний.

Отдельные объявления `import "fmt"` и `import "math"` эквивалентны группе `import (...)`.

```go
package main

import (
    "encoding/base64"
    "fmt"
    "math"
)

func main() {
    fmt.Println(math.Pow(2, 3)) // 8
    fmt.Println(base64.StdEncoding.EncodeToString([]byte("Go"))) // R28=
}
```

Путь определяет, какой пакет загружается. Разные пакеты могут иметь одно имя или одноимённые типы. Например,
`html/template.Template` и `text/template.Template` — два разных определённых типа.

### Экспортируемые имена

Имя экспортируется, если его первый символ — заглавная буква Unicode категории `Lu` и имя объявлено на уровне
пакета либо обозначает поле или метод. Правило распространяется на типы, константы и переменные уровня пакета.
Локальная переменная с заглавной буквы остаётся локальной.

```go
// Фрагмент файла с импортами "fmt" и "net/url".
address := url.URL{Host: "example.org"} // URL и Host экспортируются.
fmt.Println(address.Host)             // example.org
fmt.Println(address.String())         // //example.org
// fmt.Println(url.validEncoded)     // Ошибка: имя validEncoded не экспортируется.
```

Если `A` импортирует `B`, а `B` импортирует `C`, для обращения к имени вида `C.Item` файлу из `A` нужен
собственный импорт. Для пакетов в каталоге `internal` команда `go` ограничивает круг импортирующих пакетов
деревом, начинающимся в родительском каталоге `internal`. Например, `example.org/app/web/internal/session`
доступен из `example.org/app/web/handler`, а импорт из `example.org/app/cli` завершится ошибкой.

### Псевдоним и затенение

Явное имя перед путём решает конфликт имён пакетов в одном файле. Оно действует во всём файловом блоке.
Внутри функции локальная переменная может затенить имя импорта. Два импорта с одним именем в одном файле
конфликтуют. Имя импорта также конфликтует с одноимённым объявлением уровня пакета, даже в другом файле.

```go
package main

import (
    "fmt"
    "html/template"
    texttemplate "text/template"
)

func main() {
    fmt.Println(template.New("page").Name())     // page
    fmt.Println(texttemplate.New("note").Name()) // note
}
```

### Импорт с точкой

Точка вводит экспортируемые имена уровня пакета прямо в файловый блок. Поля и методы по-прежнему доступны через
селекторы. При конфликте с другим импортом или объявлением уровня пакета сборка завершится ошибкой. Явный
квалификатор обычно позволяет сразу увидеть источник функции.

```go
package main

import (
    . "fmt"
    . "math"
)

func main() {
    Println(Pow(2, 3)) // 8, имена Println и Pow доступны напрямую.
}
```

Два импорта с точкой для `"html/template"` и `"text/template"` конфликтуют из-за имён `New`, `Template`
и других. Конфликт возникает уже при импорте, даже если программа к этим именам не обращается.

### Неиспользуемый и пустой импорт

Обычный импорт, импорт с псевдонимом и импорт с точкой требуют использования хотя бы одного экспортируемого имени.
Использование пакета в соседнем файле не делает импорт в текущем файле использованным. Если пакет больше не нужен,
удалите импорт.

Пустой импорт `import _ "путь"` нужен, когда важен эффект инициализации пакета. Имя для обращения к пакету при этом
недоступно. Например, `image/gif` регистрирует формат GIF в пакете `image`, чтобы `image.DecodeConfig` смог
определить формат по содержимому. Пример читает размеры однопиксельного GIF, сохранённого в строке Base64.

```go
package main

import (
    "bytes"
    "encoding/base64"
    "fmt"
    "image"
    _ "image/gif" // При инициализации регистрирует формат GIF.
)

func main() {
    const pixelGIF = "R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7"
    data, err := base64.StdEncoding.DecodeString(pixelGIF)
    if err != nil {
        panic(err)
    }

    config, format, err := image.DecodeConfig(bytes.NewReader(data))
    fmt.Println(config.Width, config.Height, format, err) // 1 1 gif <nil>
}
```

Если убрать `_ "image/gif"` в этой программе, `image.DecodeConfig` вернёт `image.ErrFormat`. Когда декодер GIF нужен
напрямую, можно импортировать `"image/gif"` обычным способом и вызвать `gif.DecodeConfig`. Обычный импорт
тоже запускает инициализацию пакета.

## Граф импортов и инициализация

### Зависимости между пакетами

Импорты образуют ориентированный граф зависимостей. Пакет не может импортировать сам себя ни напрямую, ни через
цепочку вроде `A → B → A`. При таком цикле команда `go` сообщает `import cycle not allowed`. Псевдоним и `_`
не меняют ребро графа. Цикл часто устраняют, передавая зависимость через параметр или вынося общую часть
в пакет, от которого могут зависеть обе стороны.

Каждый пакет инициализируется один раз за запуск программы, даже если он импортирован из нескольких мест.
Все зависимости пакета уже инициализированы к началу его собственной инициализации. С Go 1.21 спецификация задаёт
точный порядок. Из ещё не инициализированных пакетов, чьи зависимости готовы, берётся первый в порядке сортировки
по пути импорта. Перестановка строк в группе `import` этот порядок не меняет.

### Переменные уровня пакета и функции `init`

Внутри пакета сначала инициализируются переменные уровня пакета. Среди переменных с готовыми зависимостями
берётся первая в порядке объявлений. Зависимости определяются по ссылкам в исходном коде текущего пакета,
в том числе через тела функций. Цикл инициализации переменных приводит к ошибке компиляции.
Если зависимость скрыта, например за вызовом метода через интерфейс, порядок с учётом этой зависимости
спецификация не гарантирует.

```go
package main

import "fmt"

var doubled = doubleBase() // Зависит от base через тело doubleBase.
var base = 21              // Инициализируется до doubled.

func doubleBase() int {
    return base * 2
}

func init() {
    fmt.Println(doubled) // 42, переменные уже инициализированы.
    doubled++
}

func main() {
    fmt.Println(doubled) // 43
    // init()           // Ошибка: сослаться на функцию init нельзя.
}
```

В одном пакете и даже в одном файле допустимо несколько функций `func init()`. Они выполняются последовательно
в порядке исходного текста с учётом порядка передачи файлов компилятору. Спецификация рекомендует инструментам
передавать файлы в лексикографическом порядке имён. Если порядок действий важен, выразите его прямыми вызовами.

Инициализация пакетов выполняется последовательно в одной горутине. Если `init` запускает другую горутину, та может
работать одновременно с последующей инициализацией. Для ожидания её результата нужна явная синхронизация.

## Как команда `go` находит импорт

Спецификация задаёт смысл импорта, а разрешение пути выполняют инструменты Go. В модульном режиме путь пакета
внутри модуля складывается из пути модуля и пути подкаталога. Например, для модуля `example.org/app` и каталога
`greeting` пишут `import "example.org/app/greeting"`. Запись `import "./greeting"` в модульном режиме недопустима.
В команде `go run .` точка выбирает каталог и относится к синтаксису командной строки.

- **Стандартная библиотека.** Путь `net/http` соответствует каталогу `net/http` под `GOROOT/src`. Проверить
  расположение дерева Go можно командой `go env GOROOT`.
- **Модули.** Для внешнего пакета команда ищет модуль, который предоставляет этот путь. Учитываются выбранные
  версии зависимостей. Скачанные модули хранятся в `GOMODCACHE`, по умолчанию в `pkg/mod` первого каталога
  `GOPATH`. При необходимости `go` может скачать исходники согласно настройкам, включая `GOPROXY`.
- **Режим vendor.** При выбранном режиме `-mod=vendor` зависимости сборки берутся из дерева `vendor`.

```text
go env GOROOT GOPATH GOMODCACHE
go list -f "{{.Name}} {{.Dir}}" net/http
```

Первая команда выводит значения трёх настроек по строке. Вторая показывает имя пакета `http` и каталог
его исходников в установленном дереве Go. Модули, загрузку зависимостей и `vendor` разберём дальше в главе.
